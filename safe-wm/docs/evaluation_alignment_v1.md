# SAFE-WM 평가 기준 대응 점검 v1

## 1. 주제적합성 및 문제정의

평가 기준:

- 선택 주제가 지정주제 또는 자유주제 취지와 부합하는가
- 해결하려는 문제, 대상 사용자, 사용 상황이 구체적인가
- 현행 업무의 불편, 병목, 리스크, 고객 Pain Point를 설명하는가
- 금융업 또는 JB금융그룹 관점에서 필요성이 있는가
- 실제 서비스 과제로 전환 가능한가

SAFE-WM 대응:

- 고령 고객 WM에서 수익률보다 자산 보존, 생활비 안정성, 유동성, 대출/금리 부담을 핵심 문제로 정의한다.
- 대상 사용자는 고령 고객과 PB/WM 담당자로 명확하다.
- PB가 고객별 자산 상태와 시장 변화를 일일이 종합하기 어려운 업무 병목을 해결한다.
- 고객군 중 우선 상담이 필요한 고객을 선별하므로 WM 업무 프로세스에 직접 연결된다.

보강 필요 없음. 현재 정책 문서와 구현안에 충분히 반영되어 있다.

## 2. 금융업무·사업 연계성 및 고객가치

평가 기준:

- JB금융그룹 주요 사업·업무 영역과 연결되는가
- 실제 금융 업무 프로세스 또는 고객 여정 안에서 활용 접점이 있는가
- 고객가치, 업무효율, 리스크 감소, 수익기회가 명확한가
- 규제, 보안, 개인정보, 내부통제 고려가 있는가
- 그룹 AX, 디지털 전환 취지에 부합하는가

SAFE-WM 대응:

- PB Dashboard에서 위험 고객을 우선순위화하고, 고객 상세 리포트에서 상담 포인트를 제공한다.
- 고객에게는 자산 안정성 리포트를 제공하고, PB에게는 상담 우선순위와 확인 항목을 제공한다.
- MVP는 Mock 데이터만 사용하고, 실제 서비스는 MyData 동의 기반 수집과 PB 권한 기반 접근 통제로 확장한다.
- Compliance Guard Agent로 투자권유 표현, 단정 표현, 개인정보 노출 위험을 검토한다.

보강 포인트:

- 제안서에서는 JB금융그룹 WM, 은행 PB, 고령 고객 관리 업무와 연결되는 문장을 명시해야 한다.

## 3. AI Agent 설계 및 기술적 구현 가능성

평가 기준:

- 판단·행동·검증/개선 구조를 가진 AI Agent인가
- 데이터 수집, 검색, 판단, 생성, 검증, 후속 액션 흐름이 논리적인가
- AI 모델, 데이터, RAG, Rule Engine, Multi-Agent 접근이 구체적인가
- 시스템 구성도와 기능 구조가 실제 구현 가능한가
- 외부 데이터/API 출처, 제약사항을 고려하는가

SAFE-WM 대응:

- 판단: Profile Agent와 Risk Analysis Agent가 고객 자산, 부채, 현금흐름, 시장 데이터를 해석한다.
- 행동: RAG Advisor Agent와 PB Action Agent가 고객 설명, PB 상담 요약, 후속 액션을 생성한다.
- 검증/개선: Compliance Guard Agent가 결과를 검토하고 실패 시 RAG Advisor Agent로 재생성 요청한다.
- Rule Engine은 Asset Stability Score와 Risk Grade를 고정 정책으로 계산한다.
- RAG는 `rag_guides.md` 기반 simple keyword retrieval에서 시작하고 Chroma로 확장 가능하다.
- QAIMA API, MyData, 국토교통부 실거래가, R-ONE 등 데이터 출처와 fallback을 문서화했다.

보강 완료:

- `implementation_plan_v1.md`, `architecture_v1.md`, `data_contract_v1.md`에 LangGraph, RAG, agentTrace를 추가했다.

## 4. MVP 완성도 및 검증 가능성

평가 기준:

- MVP 제안서, 기능명세서, 시연영상 간 내용이 일관되는가
- 핵심 기능이 실제 동작 가능한 MVP인가
- 기능명세서의 서비스 개요, 아키텍처, 기능, 흐름, 발전 방향이 구체적인가
- 본선 추가 개발 기반이 충분한가
- 산출물 완결성, 가독성, 제출 형식이 적정한가

SAFE-WM 대응:

- MVP는 Mock 고객 데이터 기반으로 PB Dashboard와 고객 상세 리포트를 구현한다.
- QAIMA가 꺼져도 fallback으로 동작하므로 시연 안정성이 있다.
- traceId, debug.steps, agentTrace로 에러와 Agent 흐름을 검증할 수 있다.
- 실제 데이터 확장 방향은 MyData, 부동산 공개 API, QAIMA API adapter로 분리되어 있다.

주의할 점:

- 시연에서는 대표 시나리오 1개를 깊게 보여주는 것이 좋다.
- HIGH 위험 고객 1명, MID/LOW 비교 고객을 함께 배치해 차이를 명확히 보여야 한다.

## 5. 혁신성·확장성 및 운영 리스크 관리

평가 기준:

- 기존 금융 서비스 또는 업무 방식 대비 차별성이 있는가
- 새로운 고객경험 또는 업무방식 전환 가능성이 있는가
- 계열사, 업무영역, 고객군 등으로 확장 가능한가
- PoC, 파일럿, 내부 적용, 고객 서비스화 발전 경로가 있는가
- 개인정보, 보안, 저작권, 환각, 설명가능성, 책임소재 대응 방향이 있는가

SAFE-WM 대응:

- 단순 투자추천이 아니라 자산 안정성 중심 WM AI Agent라는 점이 차별점이다.
- Rule 기반 계산, Agent 기반 리스크 해석, Compliance Loop, PB 보조 구조를 결합한다.
- 은행 WM, 증권 자산관리, 보험/연금 상담, 시니어 금융 케어로 확장 가능하다.
- LLM은 판단 주체가 아니라 설명 생성 계층으로 제한한다.
- 점수 산출 근거, risk factor evidence, agentTrace로 설명가능성을 확보한다.

보강 포인트:

- 제안서와 PPT에서 “투자 추천 금지”, “PB 최종 판단”, “상담 보조”를 반복적으로 명시해야 한다.

## 최종 판단

현재 SAFE-WM 문서 구조는 평가 기준에 대체로 부합한다.

다만 제출물 관점에서 가장 중요한 문장은 다음 세 가지다.

```text
1. SAFE-WM은 투자 추천 AI가 아니라 자산 안정성 중심 WM AI Agent다.
2. AI Agent는 판단-행동-검증/개선 구조로 동작한다.
3. 점수 계산은 Rule 기반, 리스크 해석과 설명은 Agent/LLM 기반, 검증은 Compliance Loop 기반이다.
```

이 세 문장을 제안서, 기능명세서, 발표자료, 시연 설명에 일관되게 사용한다.
